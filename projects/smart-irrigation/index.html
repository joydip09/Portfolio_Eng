Smart Irrigation System

An ESP32-powered automatic plant watering system — reads soil moisture from two sensors, controls a submersible pump via relay, and publishes live data over MQTT to a dashboard.

ESP32 Capacitive Soil Sensor 5V Relay Mini Pump MQTT OLED Display
01 — Problem

Why I Built This

Plants in my room kept dying — not from neglect exactly, but from inconsistency. Sometimes I'd water too much, sometimes too little. It was pure guesswork based on how dry the soil looked. I wanted to replace intuition with data.

The goal: an automated system that reads actual soil moisture levels and triggers a pump only when needed, with real-time monitoring accessible from my phone over Wi-Fi. No cloud dependency — just a local MQTT broker on my home network.

02 — Planning

System Architecture

The system is built around four layers:

  • Sensing — Two capacitive soil moisture sensors (chosen over resistive for longevity)
  • Decision — ESP32 compares readings against configurable dry/wet thresholds
  • Actuation — 5V relay switches the submersible pump on/off
  • Reporting — MQTT publishes sensor data + pump state every 30 seconds

Why Capacitive Sensors?

Resistive soil sensors corrode within weeks due to electrolysis. Capacitive sensors measure the dielectric constant of soil — no exposed electrodes, no corrosion. They cost slightly more but last indefinitely.

Why Local MQTT vs. Cloud?

No internet dependency, no latency, no subscription fees. Mosquitto broker running on a Raspberry Pi on my home network. Node-RED handles the dashboard visualization.

05 — Implementation

Firmware & MQTT Logic

The ESP32 reads both soil sensors every 30 seconds, maps the ADC values to a 0–100% moisture percentage (calibrated per sensor), and publishes JSON payloads to an MQTT broker. If either sensor reads below the dry threshold, the pump activates for a configurable duration.

C++ (ESP32 Arduino) Copy 
// Thresholds — calibrate to your soil + sensor
const int DRY_THRESHOLD  = 30;   // % — below this, water
const int WET_THRESHOLD  = 70;   // % — above this, stop
const int PUMP_DURATION  = 3000; // ms per watering cycle

void loop() {
  int raw1 = analogRead(SENSOR_PIN_1);
  int raw2 = analogRead(SENSOR_PIN_2);

  int moisture1 = map(raw1, AIR_VAL, WATER_VAL, 0, 100);
  int moisture2 = map(raw2, AIR_VAL, WATER_VAL, 0, 100);

  // Publish to MQTT
  String payload = "{\"s1\":" + String(moisture1)
                 + ",\"s2\":" + String(moisture2)
                 + ",\"pump\":" + String(pumpActive) + "}";
  client.publish("garden/sensors", payload.c_str());

  // Auto-water logic
  if (moisture1 < DRY_THRESHOLD || moisture2 < DRY_THRESHOLD) {
    activatePump(PUMP_DURATION);
  }

  updateOLED(moisture1, moisture2);
  delay(30000); // 30 second interval
}
⚠️
Sensor Calibration is Critical
Each capacitive sensor has slightly different AIR_VAL and WATER_VAL readings. Calibrate each one individually by reading in completely dry soil and submerged in water. Don't assume they match the datasheet.
06 — Troubleshooting

Failures & Fixes

💧
Pump Wouldn't Stop — Relay Stuck Closed
First relay module didn't have an optocoupler — ESP32 GPIO couldn't reliably drive it and it would latch. Switched to an optocoupler-isolated relay module. Never looked back.
📡
Wi-Fi Disconnects After ~6 Hours
ESP32 was losing Wi-Fi connection overnight. Root cause: router DHCP lease expiry wasn't handled gracefully. Fix: added reconnection logic in the MQTT loop callback and assigned a static IP on the router side.
🔢
ADC Noise on ESP32
ESP32 ADC is notoriously noisy, especially on ADC2 pins (which share with Wi-Fi). Moved both sensors to ADC1 pins and added a 10-sample moving average. Readings stabilized significantly.
07 — Results

Final Performance

  • Uptime: 30 days continuous without manual intervention
  • Sensor accuracy: ±3% across calibrated range
  • MQTT latency: Under 200ms on local network
  • Plants: All survived. One thrived noticeably more than before.

08 — Reflection

What I Learned

This project taught me the value of proper sensor selection upfront. The resistive sensor I initially bought corroded within a week. Spending slightly more on capacitive sensors saved rebuilding the whole thing.

The ESP32 ADC noise issue was a deep rabbit hole — I didn't expect a microcontroller to have such quirky ADC behavior. The Wi-Fi coexistence issue on ADC2 pins is a known hardware limitation that's easy to miss if you don't read the datasheet carefully.

What I'd Do Differently

  • Design a proper PCB to replace the jumper-wire prototype
  • Add a water level sensor in the reservoir to alert when empty
  • Implement OTA firmware updates via ESP32's built-in OTA library
  • Add a manual override button on the enclosure
