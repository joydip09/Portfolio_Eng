Line Follower Robot

An autonomous PID-controlled robot that follows a black line at speed — built from scratch with an Arduino Uno, L298N motor driver, and a 5-channel IR sensor array.

Arduino Uno L298N Motor Driver IR Sensor Array TT Motors PVC Chassis 18650 Li-Ion
01 — Problem

The Idea

I wanted to build a fully autonomous robot that could follow a predefined path reliably — something that actually moves at speed without constantly overcorrecting. The classic bang-bang control felt clunky. I wanted smooth, responsive motion using proper PID control.

The challenge: tuning a PID controller on physical hardware is fundamentally different from simulation. Sensor noise, motor lag, battery sag — all of these make a textbook PID formula behave unpredictably. I had to earn this one through trial and error.

02 — Planning

Design & Architecture

The system was designed around three layers:

  • Sensing — 5-channel IR sensor array reading line position as a weighted average
  • Control — PID loop computing correction from sensor error
  • Actuation — L298N motor driver applying differential speed to both motors

Key Design Decisions

  • PVC chassis for rigidity and lightweight construction
  • Weight balanced toward front to improve turn response
  • Buck converter for stable 5V logic — batteries sag under load
  • 5-channel sensor for better position resolution vs. 3-channel

05 — Implementation

Firmware & PID Logic

The core of the firmware is a PID loop running every 10ms. The sensor array outputs a position value from –4 (far left) to +4 (far right), with 0 meaning perfectly centered. This error feeds into the PID formula:

C++ (Arduino) Copy 
// PID Constants — tune these for your track
float Kp = 1.2, Ki = 0.0, Kd = 0.8;

float lastError = 0, integral = 0;

void loop() {
  int position = readSensorArray();   // returns -4 to +4
  float error  = position;            // setpoint is 0 (center)

  integral  += error;
  float derivative = error - lastError;

  float correction = Kp * error
                   + Ki * integral
                   + Kd * derivative;

  int leftSpeed  = BASE_SPEED - correction;
  int rightSpeed = BASE_SPEED + correction;

  // Clamp to 0–255 PWM range
  leftSpeed  = constrain(leftSpeed,  0, 255);
  rightSpeed = constrain(rightSpeed, 0, 255);

  driveMotors(leftSpeed, rightSpeed);
  lastError = error;
  delay(10);
}
💡
PID Tuning Tip
Start with Ki = 0 and Kd = 0. Tune Kp until it follows the line but oscillates. Then increase Kd until oscillation stops. Ki is rarely needed for line followers.
06 — Build Timeline

Week by Week

Week 1
Concept & Planning
Chose PID over bang-bang. Sketched chassis layout. Sourced components from local electronics market.
Week 2
Hardware Assembly
Cut PVC chassis. Mounted motors and caster. Wired motor driver to Arduino. First movement test.
Week 3
Sensor Calibration
Wrote calibration routine. Found sensor 3 giving noisy readings — discovered cold solder joint. Re-soldered, fixed.
Week 4
PID Tuning
Manually tuned Kp, Ki, Kd over 6 hours. Kd was the game changer — killed the oscillation completely.
Week 5
Track Testing & Refinement
Final track testing. Added weight to front. Final performance: 0.8 m/s on curves, 1.1 m/s on straights.
07 — Troubleshooting

Failures & Fixes

⚠️
Noisy Sensor Output
Sensor 3 was giving inconsistent digital readings. Root cause: cold solder joint on the sensor header pin. Fix: re-soldered with proper flux.
⚡
Battery Sag Causing Erratic Behavior
Under load, battery voltage dropped from 7.4V to 6.1V, making the motors respond differently. Fix: added 1000µF capacitor across motor power rails and added the buck converter for stable 5V logic.
🔄
Oscillation at High Speed
Kd was initially 0.1 — not enough damping. Robot would overshoot and oscillate on curves. Increased Kd to 0.8, which provided sufficient damping without slowing response.
08 — Results

Final Performance

  • Top speed on curves: 0.8 m/s
  • Top speed on straights: 1.1 m/s
  • Track completion: 10 consecutive laps without losing line
  • Final PID values: Kp=1.2, Ki=0.0, Kd=0.8

09 — Reflection

What I Learned

This project taught me that PID tuning is fundamentally an empirical process. The textbook equations give you a starting point, but the physical world — sensor noise, mechanical slop, power supply variations — means you're always tuning on hardware, not in simulation.

The battery sag issue was the most educational failure. I didn't anticipate that voltage fluctuation under load would affect the PID response so dramatically. Adding proper power filtering is now standard in all my subsequent projects.

What I'd Do Differently

  • Use encoders on wheels for closed-loop speed control
  • Add a proper PCB instead of jumper wire rats nest
  • Implement auto-tuning using Ziegler–Nichols method
  • Consider a faster microcontroller (ESP32) for better loop frequency
